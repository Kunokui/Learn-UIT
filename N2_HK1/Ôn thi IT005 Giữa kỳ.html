Tóm tắt kiến thức

C1 Độ trễ & thông lượng

dnodal = dproc + dqueue + L/R + d/s
  • L/R: trễ truyền (đẩy bit ra đường truyền)
  • d/s: trễ lan truyền (bit đi hết quãng đường)
  • Cường độ lưu lượng La/R: gần 1 thì trễ hàng đợi tăng vọt, >1 thì vô hạn
  • Thông lượng đầu cuối = min các liên kết (nút cổ chai); n kết nối chia đều R → R/n
  • Đổi đơn vị: 1 Mbps = 10⁶ bps; km → m

C1 Mô hình phân tầng

  • OSI 7 tầng (trên → dưới): Application, Presentation, Session, Transport, Network, Data Link, Physical
  • Internet 5 tầng: bỏ Presentation và Session
  • PDU: Message → Segment → Datagram → Frame
  • Thêm header khi đi xuống = Encapsulation
  • Switch xử lý tới tầng 2 (Link), Router tới tầng 3 (Network)
  • Mã hóa, nén dữ liệu: Presentation. Mở/duy trì/đóng phiên: Session

C1 Chuyển mạch gói vs kênh

  • Kênh: tài nguyên dành riêng, phải thiết lập cuộc gọi, hiệu năng đảm bảo (điện thoại)
  • Gói: chia sẻ tài nguyên, store-and-forward, không cần thiết lập, có thể mất gói và trễ hàng đợi
  • Phân kênh: FDM (tần số), TDM (khe thời gian)
  • Store-and-forward qua N liên kết: N·L/R

C2 HTTP

  • TCP cổng 80; stateless (trạng thái giữ bằng cookie)
  • Không bền vững (HTTP/1.0): 2 RTT + thời gian truyền mỗi đối tượng, mỗi đối tượng một kết nối
  • Bền vững (HTTP/1.1): giữ kết nối, ~1 RTT mỗi đối tượng (pipeline: 1 RTT cho tất cả)
  • Mã: 200 OK · 301 Moved Permanently · 304 Not Modified · 400 Bad Request · 404 Not Found · 505 Version Not Supported
  • If-Modified-Since: client đã có bản cache; 304 trả về không có dữ liệu
  • URL đối tượng = Host + đường dẫn trong dòng GET

C2 Email, FTP

  • SMTP: TCP cổng 25, push; client: HELO → MAIL FROM → RCPT TO → DATA → QUIT
  • Agent → server, server → server: SMTP. Server → agent của người nhận: POP3 / IMAP / HTTP
  • POP3: tải về, không giữ trạng thái giữa các phiên. IMAP: thư và thư mục ở server, giữ trạng thái
  • FTP: điều khiển cổng 21, dữ liệu cổng 20, out-of-band, server giữ trạng thái

C2 DNS, P2P, Socket

  • DNS: UDP cổng 53; phân cấp Root → TLD → Authoritative; Local DNS không thuộc phân cấp
  • Lặp: server trả “hỏi tiếp ở X”. Đệ quy: server hỏi giúp đến khi có đáp án
  • Bản ghi: A (tên → IP), NS, CNAME (bí danh), MX (mail server)
  • Phân phối file: DC-S ≥ max(NF/us, F/dmin); DP2P ≥ max(F/us, F/dmin, NF/(us+Σui))
  • SOCK_STREAM = TCP, SOCK_DGRAM = UDP; bind/listen/accept = server TCP; connect = client TCP; recvfrom/sendto = UDP

C3 UDP & dồn/phân kênh

  • Header 8 byte: Source port · Dest port · Length · Checksum (mỗi trường 16 bit)
  • Length tính cả header → payload = Length − 8
  • Checksum: cộng bù 1 các word 16 bit, có bit tràn cộng vòng, rồi đảo bit
  • Socket UDP xác định bởi (IP đích, port đích); TCP bởi bộ 4 (IP nguồn, port nguồn, IP đích, port đích)
  • Tầng vận chuyển không đảm bảo độ trễ hay băng thông

C3 rdt, GBN, SR

  • rdt1.0 kênh tin cậy · rdt2.0 lỗi bit (ACK/NAK) · rdt2.1 thêm số thứ tự (ACK/NAK hỏng) · rdt2.2 bỏ NAK · rdt3.0 thêm timer → xử lý mất gói
  • GBN: ACK tích lũy, bên nhận bỏ gói sai thứ tự và gửi lại ACK gói đúng gần nhất; timeout → gửi lại mọi gói chưa ACK
  • SR: ACK từng gói, đệm gói sai thứ tự, chỉ gửi lại gói bị mất

C3 TCP

  • Seq = số thứ tự byte đầu tiên; ACK = byte kế tiếp mong đợi (tích lũy)
  • Bắt tay 3 bước: SYN(seq=x) → SYNACK(seq=y, ack=x+1) → ACK(ack=y+1). ISN ngẫu nhiên 0…2³²−1
  • 3 ACK trùng → fast retransmit
  • EstimatedRTT = 0.875·Est + 0.125·Sample; Timeout = Est + 4·DevRTT
  • Reno: slow start ×2 mỗi RTT tới ssthresh; CA +1 MSS/RTT; 3 dup ACK → ssthresh = cwnd/2, cwnd = ssthresh; timeout → ssthresh = cwnd/2, cwnd = 1

Cách giải các dạng tính toán

Tìm Rnew để giảm một nửa độ trễ đầu cuối

Đề: L = 30 000 bit, R = 10 Mbps, d = 300 km, s = 3·10⁸ m/s. Khoảng cách mới d/2, muốn độ trễ còn một nửa.

trễ cũ = 30000/10⁷ + 3·10⁵/3·10⁸ = 3 ms + 1 ms = 4 ms
trễ mới cần = 2 ms; lan truyền mới = 0.5 ms → truyền = 1.5 ms
Rnew = 30000 / 1.5 ms = 20 Mbps = 2R

Luôn tính riêng hai phần, trừ phần lan truyền ra, rồi mới suy R.

Giải mã UDP header từ 64 bit

Cắt chuỗi 64 bit thành 4 cụm 16 bit theo thứ tự Source · Dest · Length · Checksum, đổi sang thập phân.

11101001 00110001Source = 59697
00000000 00110101Dest = 53 (DNS)
00000000 00101111Length = 47
11111110 00010111Checksum

Payload = 47 − 8 = 39 byte. Bẫy hay gặp: chọn 47 (quên trừ header) hoặc lấy nhầm cụm đầu làm cổng đích.

Sequence number và ACK trên sơ đồ

ISN = 161, mỗi segment 281 byte. Dãy seq: 161, 442, 723, 1004, 1285 (cộng dồn 281).

ACK luôn là byte kế tiếp bên nhận đang chờ. Nếu segment 1 mất, mọi segment đến sau đều nhận ACK = 161 (ACK trùng). Nếu segment 1 và 2 đến, ACK = 723.

Go-Back-N: bên nhận chỉ chấp nhận đúng thứ tự, nên một gói mất kéo theo gửi lại gói đó và mọi gói phía sau trong cửa sổ.

Đọc đồ thị cwnd TCP Reno

Đồ thị mẫu dưới đây được dùng cho các câu Reno trong phần trắc nghiệm.

  • Đoạn nhân đôi (1, 2, 4, 8, 16): slow start. Điểm chuyển sang tăng tuyến tính là ssthresh (ở đây 16).
  • Đoạn tăng +1 mỗi vòng: congestion avoidance.
  • Rớt còn một nửa: 3 ACK trùng. Rớt về 1: timeout. Cả hai đều đặt ssthresh = cwnd/2 lúc mất gói.
  • Segment thứ n: cộng dồn cwnd từng vòng (1, 3, 7, 15, 31, 48…) tới khi vượt n.
